# 传播方向对照：看见的力量

用户明确的产品灵感来自现实中的便利贴和书签：便利贴贴在上面才会被注意，书签露在书页外才会再次被看见。记录被最小化成一个看不见的窗口后，可能失去再次提醒自己的机会。

**这是「看见」的力量。**

这句话作为产品主张；第一次接触产品的读者，还需要一句能立刻理解的用途说明：**记下，也要看见。**

## A 与 B 的差别

| | A：用时在眼前，不用靠边站 | B：记下，也要看见 |
| --- | --- | --- |
| 先传递的价值 | 便签能收起、贴边，给桌面让出空间 | 记下的东西持续进入视线，不随切换窗口被遮住 |
| 画面重点 | 展开、横条、贴边书签的形态变化 | 多个工作窗口叠放，真实便签始终位于它们上方 |
| 记忆点 | 这个便签会靠边站 | 这是「看见」的力量 |
| 纸质原型 | 屏幕边缘像书签 | 便利贴贴在眼前；书签露在书页外 |
| 适合的位置 | 第二屏的交互展示、GIF、功能短视频 | README 首屏、品牌主张、首发故事 |

建议让 B 承担产品主张，把 A 的贴边动作放在后面作证明。收起后留下的小书签也属于「看见」：需要空间时可以减少遮挡，同时在边缘留下一个视觉线索。

这种表达不以整理清单或承诺提高效率为中心。它强调一个更直接、可看见的行为：**让你希望再想起的事，继续出现在工作视线里。**

## 已采用的表达

README 第一屏：

> **记下，也要看见。**
>
> 一张始终置顶的桌面便利贴。
>
> 这是「看见」的力量。

收起与贴边部分：

> **留在眼前，也懂得让开。**
>
> 像书签露在书页外一样，把便签收成横条，贴到屏幕边。需要时，再拖出来展开。

小红书首选标题：**我想做的，是一张看得见的便签**

正文：

> 有些事，认真记下了，却没再看过。
>
> 写进待办，最小化窗口，再打开几个页面。刚才记下的事，就这样退出了视线。
>
> 我做「悬浮便签」时，想到的是桌边那张便利贴，还有露在书页外的一小截书签。
>
> 它们很简单，但会再次被看见。
>
> 所以这张便签会一直置顶在普通工作窗口上方。你切换文档、打开网页，待办、灵感和参考图还留在眼前。
>
> 需要给工作腾点地方，就把它收起来，贴到屏幕边上，留一枚小书签。
>
> 这是「看见」的力量。
>
> 免费开源，Windows 和 Apple Silicon Mac 可用。项目叫「悬浮便签」，GitHub 搜索 LawrenceChiu95 / floating-sticky-notes。

## 事实与来源

- 当前实现为 `alwaysOnTop: true`，并使用 Electron 的 `floating` 置顶层级。面向用户写「始终置顶在普通工作窗口上方」，不写「高过所有系统窗口」；本轮不修改层级或原生窗口行为。
- 不宣称看见一定等于完成，也不编造用户测试、效率提升数据或竞品缺陷。关于最小化的描述是一个使用场景，不泛指所有其他便签工具。
- 便签图使用与 A 版一致的真实 renderer 截图，工作窗口为示意布景。纸质场景为本次 imagegen 生成的概念图，不是产品实拍；中文由 HTML 排版。
- A 版原始图片和 README 保留。B 版文件为 `assets/showcase/seen/`、`source/seen.html`，已采用到根目录 `README.md`；本文同目录下的 `README-seen.md` 是预览副本。当前小红书成稿以 `xiaohongshu.md` 和 `assets/showcase/xhs-b/` 为准。

状态与授权沿用 [Issue #30](https://github.com/LawrenceChiu95/floating-sticky-notes/issues/30) 和本机 HANDOFF，不在此维护另一套进度表。

首屏移除了不易识别的粉色书签；“也懂得让开”随收边演示放在后续段落，不依靠小标签让新用户猜功能。新增六秒置顶演示，在普通工作窗口切换时保持同一张真实便签的位置不变；工作窗口仍为虚构布景，不称作系统操作录屏。
