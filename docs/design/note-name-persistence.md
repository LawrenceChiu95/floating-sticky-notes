# 便签名称常驻与视觉层级设计

## 背景

`0.1.11` 首次支持为便签命名，并把名称同步到 Windows 任务栏预览和 Alt-Tab。当时便签正面的名称只在中央命名热区悬停、编辑中或保存成功后的短暂确认期显示；鼠标移开后重新隐藏。

真实用户把名称理解为便签的持续身份，认为“鼠标移开就消失”代表功能失效，同时反馈当前名称过于不显眼。原设计希望保持纸面安静，但把“视觉弱化”做成了“完全隐藏”，削弱了命名功能用于扫视区分便签的价值。

Windows 任务栏预览已经能正常跟随便签名称，不属于本次问题。

## 目标

- 已命名便签无需鼠标操作即可看到名称。
- 名称保持安静，不压过正文和清单内容。
- 常驻名称仍能提示用户可以双击编辑。
- 未命名便签不常驻显示操作提示。
- 名称保存失败时保留用户输入，允许直接重试。
- 保持现有拖动区域、工具按钮和窄窗口可用。

## 非目标

- 不增加独立标题行、重命名按钮或右键菜单。
- 不改变名称存储格式、60 个 Unicode code point 上限或系统窗口标题规则。
- 不改变 Windows 任务栏预览、Alt-Tab、应用身份或窗口分组方式。
- 不扩展到分类、标签、文件夹或工作区，也不改变既有命名数据模型。
- 不处理整个便签在最低透明度下叠加任意桌面背景时的全局对比度问题。

## 已选视觉方案

### 已命名静止态

- 非空名称始终可见，不再依赖 hover 或保存确认 class 才恢复 opacity。
- 名称使用 `12px`、`font-weight: 600`。
- 名称使用统一的克制墨色 `rgba(43, 42, 39, 0.82)`；现有五种可选便签色均为浅色，不引入动态前景色算法。
- 名称保持单行和省略号截断；展开态不再为已可见的名称重复显示原生 tooltip。
- 只调整名称本身，不放大或加粗共用的临时状态文案。

### 已命名悬停态

- 静止时只显示文字。
- 鼠标进入名称热区后增加 `rgba(43, 42, 39, 0.07)` 的圆角底色，提示该区域可以编辑。
- 保留文本鼠标指针和双击编辑，不增加图标、下划线或常驻按钮。

### 编辑态

- 输入框继续原地替换名称，不新增布局行。
- 输入框与常驻名称使用相同的 `12px / 600`，避免进入编辑时发生视觉跳变。
- 进入编辑时工具栏折叠让位，展开态与收起态使用相同的 `160×20px` 长槽、左右 `6px` padding、居中文字与 `6px` 圆角；窄窗口允许在可用空间内收缩。
- 输入框维持无边框、透明外观；聚焦或编辑时使用与悬停态一致的弱底色。
- `Enter` 或失焦提交，`Esc` 取消并恢复编辑前的已保存名称。

### 未命名态

- 空名称静止时保持空白。
- 只有鼠标进入中央命名热区时，才显示常规字重、弱化颜色的“`双击命名`”，并使用同一弱底色。
- 清空名称保存成功后直接回到未命名空态，不额外显示“名称已移除”。

## 状态与数据流

显示优先级保持为：

```text
正在编辑或保存名称 > 临时状态 > 已保存名称 > 未命名 hover 提示 > 空白
```

1. 双击名称或空名称热区后，renderer 以当前已保存名称创建 draft，并聚焦、全选输入框。
2. 用户按 `Enter` 或让输入框失焦后，renderer 提交 draft。保存请求完成前保留输入框和 draft，并阻止重复提交。
3. 主进程继续在可信边界执行 trim 和 60 code point 截断，先持久化，再更新原生窗口标题，最后返回规范化后的名称。
4. 保存成功后，renderer 使用主进程返回值替换本地名称并退出编辑；非空名称立即进入常驻静止态，空名称进入未命名空态。
5. 保存失败后，renderer 保持编辑态和原 draft，解除提交锁，并用错误描边与 `aria-live` 文案“保存失败”反馈。Enter 提交时输入框自然保持焦点；失焦提交时不强制抢回焦点，尊重用户已切换到其他区域的意图。用户可以再次点击名称修改或重试，也可以按 `Esc` 取消。
6. 无关的临时状态不能卸载正在编辑或等待保存的名称输入框。未编辑时，临时状态可以短暂覆盖常驻名称，结束后恢复名称。

保存成功后不再需要“名称显示约 1.5 秒后重新隐藏”的确认状态或定时器。

## 顶栏与窄窗口约束

- 名称热区继续使用 `-webkit-app-region: no-drag`，宽度跟随名称内容，并在可用空间内收缩，最大不超过 `160px`。
- 静止态名称槽按内容在 `72..160px` 内适配；编辑槽在可用空间内增长到最大 `160px`。收起态双击时从实测静止槽宽度向两侧连续增长，不能先在左侧闪现再跳到中心。
- 顶栏一级操作为“新建 / 待办 / 删除 / 更多”与独立收起按钮。删除使用顶栏内联确认控制风险；“更多”只承载外观和从剪贴板贴图。
- “更多”菜单与便签纸面视觉语言的后续打磨由 [#15](https://github.com/LawrenceChiu95/floating-sticky-notes/issues/15) 独立跟踪，不重新打开已定稿的一级动作层级。
- 默认宽度的四个工具按钮均为 `26px`，`220px` 及以下为 `20px`；左侧抓手容器分别为 `28px` 和 `22px`。按钮高度仍为 `22px`，不改变顶栏纵向尺寸。
- 展开态名称在当前标题轨道内居中，编辑输入框在工具栏让位后居中；收起态名称和输入框都以整个窗口中心为不变量。折叠/展开期间冻结展开标题轨道宽度，避免工具栏收放带着名称横向漂移。
- 名称区域允许随可用空间收缩并以省略号截断，不得覆盖抓手或右侧工具按钮。
- `220px` 及以下窗口压缩一级工具按钮间距和单键宽度，确保 `200px` 最小宽度下四个一级工具按钮和收起按钮仍留在窗口内；名称可以按剩余空间截断。
- 进入命名编辑时，一级工具栏以与收起动效一致的方式折叠让位；收起按钮保持原位，输入框在 `200px` 窗口中实测可获得约 `136px`，并继续受 `160px` 最大宽度约束。
- 已命名展开态不挂原生 tooltip；hover 的弱底色只提示可编辑。收起横条保留标题属性用于查看被截断的名称。
- 必须人工检查 `200px` 最小宽度、`280px` 默认宽度和较宽窗口；极窄窗口可以更强地截断名称，但抓手和工具操作不能失效。

## 错误与无障碍

- 名称保存失败不能丢弃 draft，也不能静默回退后要求用户重新输入。
- 失焦触发的保存失败不能强制夺回焦点；错误状态和 draft 保留在输入框中，等待用户自行返回处理。
- 错误描边只作用于名称输入框，不改变整个顶栏或便签颜色；使用 `1px solid rgba(185, 28, 28, 0.55)`，用户再次修改或重试时清除。
- 错误描边提供可见反馈，同时通过现有 `aria-live` 区域播报“保存失败”。
- 保存等待期间输入框设置 `aria-busy="true"`，并阻止 Enter、blur 或双击触发第二次保存。
- 长名称继续省略截断；键盘行为和输入法组合输入处理保持现状。

## 测试与验收

### 自动化

- 命名状态测试覆盖：非空名称常驻展示、空名称提示、保存成功使用规范化返回值、保存失败保留 draft 和编辑态、重复提交被阻止、`Esc` 恢复旧名称。
- renderer wiring 测试覆盖：已命名与未命名使用不同显隐 class，移除 1.5 秒隐藏确认逻辑，编辑器优先于无关临时状态。
- 样式测试覆盖：名称为 `12px / 600`、已命名默认可见、空名称默认隐藏、悬停弱底色、显示态与输入框按内容使用相同的响应式宽度、命名编辑时工具栏让位。
- 几何预算测试从实际 CSS 度量与一级按钮数量复算 `280px` / `200px` 的名称文字空间，并锁定两种收起窗口宽度的精确中心、展开态居中以及过渡期冻结轨道的布局契约。
- 现有主进程名称归一化、持久化和原生窗口标题测试继续通过。

### 人工

- 在默认宽度确认名称常驻、视觉弱于正文但可扫视识别。
- 检查已命名 hover、双击、Enter、失焦、Esc、长名称省略，以及展开态没有重复原生 tooltip。
- 检查未命名静止为空白、中央热区 hover 显示“双击命名”。
- 模拟保存失败，确认 draft 未丢失、错误反馈可见并可重试；从输入框点到正文触发失败时，正文焦点不被夺回。
- 检查 `200px`、`280px` 和较宽窗口中的一级工具栏、更多菜单、抓手、名称截断、命名让位和拖动行为；收起态展示槽、动画每一帧和最终编辑槽必须保持同一中心。
- 检查五种便签颜色以及 `0.3`、默认值和 `1` 三档透明度。
- 在 Windows 与 macOS 开发版验证常驻、悬停、编辑和拖动；Windows 任务栏预览与 Alt-Tab 只做回归确认，不改变既有逻辑。
