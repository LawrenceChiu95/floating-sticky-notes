# 收起横条贴边吸附

> **现状（2026-08-21）：** 形状 96×32 横书签头；吸附/展开/悬停探头的拖动手感与进出动画已在 Mac 真机全部过验收。终版判定模型是「**松手才吸**」（物理按键监视器权威判定松手，拖动全程零写窗），吸附 320ms 纯平移滑行 + DOM 交叉淡变，展开 340ms clip 揭示。功能仍在 `feat/issue-24-edge-dock`，未合 main、未发布；Windows 真机未验证。

## 背景

现有收起把便签变成仍留在桌面上的 40px 标题横条。横条置顶、可拖、可命名，但大部分时间挡在桌面或窗口上；截网页或应用窗口时也容易拍进去。

用户日常只在做完一件事时才需要把待办拖出来打勾，其余时间希望它像安全管家加速球一样吸在屏幕侧面，只露一条边。

本设计处理 [Issue #24](https://github.com/LawrenceChiu95/floating-sticky-notes/issues/24)。

## 目标

- 已收起的横条可以吸到当前屏幕左或右工作区边缘，收成一枚可拖的彩色书签头。
- 书签头静止时半藏在屏外（露 48px）；鼠标悬上去整条 96px 滑出贴边，移开滑回半藏。
- 不悬停也可以直接抓住半藏条往桌面里拖，过阈值立即在原地长成上次展开的宽高。
- 贴边状态写入 `notes.json`，重启后贴回原来那块屏的同一条边；只收成横条、未贴边的便签重启后仍展开。
- 贴边后截某个窗口或页面时，不再拍到 40px 横条。
- 贴边与现有收起共用同一个窗口控制器；**吸附是承诺式的「松手才吸」**（2026-08-21 定稿，「磁吸不等松手」被真机否掉后修订）：拖动全程零写窗（横条跟手自由拖），拖进吸附区只显示「松手贴边」预览提示，物理松手确认后才执行吸附（320ms 滑入动画）；**展开仍是拖动中过阈值立即展开**（拖出书签头不能等松手，340ms 揭示动画）。

## 非目标

- 不从展开态直接贴边，也不提供贴边回到横条的专用动作。
- 不吸顶边或底边。
- 不把横条收起状态写入 `notes.json`。
- 不调用 `setContentProtection` 或任何“从截图/录屏中排除窗口”的 API。
- 不做全局快捷键呼出、点击书签头展开。
- 不改变安装身份、`userData` 路径、开机启动或更新流程。
- 第一版不为多张贴边便签做智能分组；只在即将重叠时沿边错开，保证都能抓住。

## 已选方案

在现有收起控制器上增加第三态，窗口状态为：

`expanded` → `collapsed`（40px 横条）→ `docked`（左/右 96×32 横书签头）

三个态的窗口拖动全部走原生 `-webkit-app-region: drag`，与系统拖窗同一条路径——自定义拖窗（renderer 指针 + IPC 移窗、主进程轮询跟光标）在真机上始终比原生慢一拍，已废弃。贴边/展开是磁吸：主进程在拖动产生的 `move` 事件上看当前矩形，过阈值立即改几何。180ms ease-out 滑行（`glideNoteWindowTo`）只用于悬停探头（拖动已停、没有拖拽会话争写）；吸附与展开都在拖动途中触发，必须一次性落位（逐帧写入会被拖拽会话吞掉，见「风险」）。

### 书签头 = 环 + 芯（悬停能进能出的关键）

macOS 上 `-webkit-app-region: drag` 的区域在**应用非激活时收不到 OS 的 enter/leave**（mousedown 与原生拖动不受影响），no-drag 区双向照收——2026-08-19 真机对照实验证实。用户悬停书签头时几乎都停在别的应用里，所以书签头不能整面 drag。结构：

- 外壳 `.note-shell--docked` 永久 `no-drag`，承载全部视觉（便签色、边框、圆角、阴影），同时是悬停传感区；
- 内嵌 5px 的透明 `.dock-tab-pill`（`position:absolute; inset:5px`）是永久 drag 的拖动面，休息/探出都可直接抓取；
- 光标进出窗口必先跨那圈 5px no-drag 环，应用非激活时 enter/leave 也能送达（对照实验 6/6）。

半藏与露出纯靠窗口几何：窗口恒为 96 宽，休息位一半探出屏外（露 48px），露出位整条贴边；DOM 永远铺满窗口，进出贴边没有壳体尺寸过渡。多屏共边（隐藏半幅会漏到邻屏）时退回 48 宽全露。

### 悬停探头：事件只是扳机，光标真相说了算

- renderer 的 `mouseenter/leave` 只发 `sticky-notes:dock-peek` 意图；主进程每次都用一次性 `screen.getCursorScreenPoint()` 判定真实悬停再滑行（单次查询合法，红线是轮询跟光标做拖动）。
- 扳机撞上吸附/展开/探头滑行（inFlight）不丢：记下 pending，每次贴边态滑行收尾都用光标真相补一发 reconcile，「缩回途中光标折返」等断拍自愈。
- **leave 兜底轮询**：应用非激活时 OS 的 mouseleave 不是 100% 可靠（实测快速甩出、贴屏边滑走会丢），丢了就卡死在露出。露出期间每 120ms 复核一次「光标还在不在窗内」，不在就走与 leave 相同的收缩路径；缩回半藏、展开、拖出、关窗即停。只读光标位置、不逐帧驱动窗口，与被否的轮询拖窗无关。
- **抢拖熔断**：探头滑行途中用户抓住书签头抢拖时，第一帧偏离滑行走廊（y 偏 >2px 或 x 出 [minX-2, maxX+2]）的 move 就熔断滑行、把几何交还拖拽——原生拖拽会话进行中争写 setBounds 会被吞，控制器/几何/DOM 三方脱臼（fast-drag 变形同款根因）。

### 展开只认「用户正抓着书签头」

启动恢复半藏位后，macOS 会在 show 时把探出屏右缘的窗口拉回屏内（实测最右屏右缘 4222→4174，恰好 48px），这一帧非拖动 move 若过 48px 阈值会误展开、dock 还会被当失效丢弃。原生拖动中光标必在窗内（抓取点偏移恒定），所以过阈值的 move 先查光标在不在窗内：不在 → 钉回静止位，不展开。

## 人怎么用

| 状态 | 外观 | 是否持久化 |
| --- | --- | --- |
| 展开 | 现有完整便签 | `bounds` 记展开位置和尺寸 |
| 横条 | 现有 40px 标题横条 | 不记；重启当展开 |
| 贴边 | 工作区左或右缘一枚 96×32 彩色书签头，静止半藏露 48px，悬停露整条；颜色跟随该便签 | 记 `dock.side`、`dock.y` 与 `dock.x` |

进出：

- 展开 ↔ 横条：现有收起按钮，行为不变。
- 横条 → 贴边：拖横条，左/右缘探出工作区对应缘 8px（光标顶到屏幕边，路过不误吸）时横条上显示「松手贴边」承诺提示（只发 IPC 状态，不写窗）；**物理松手确认后**才执行吸附：窗口保持横条尺寸纯平移 320ms 滑向贴边（书签头 DOM 钉保留角交叉淡变），到位一次性裁成书签头。松手时不在吸附区就什么都不发生。
- 悬停：书签头静止时半藏；鼠标悬上去整条 96px 滑出，移开滑回半藏。
- 贴边 → 展开：拖书签头（半藏或露出状态都可直接抓）。水平离边达到 48px 立即在当前位置用上次展开宽高长开（340ms clip 揭示：纸面从书签头矩形长成全窗），拖动不中断；不足 48px 时窗口跟手自由拖（move 流零写窗），松手停稳后若位置有偏再 180ms 惰性滑回钉边。
- 滑行途中（吸附 320ms / 钉回 180ms / 探头 180ms）随时可抓住窗口抢拖：物理按下即熔断滑行、几何交还拖拽。
- 左边贴边往右长，右边贴边往左长，长开后夹进工作区，避免先冲出屏幕再回弹。
- 不允许展开 → 贴边，也不提供贴边 → 横条。

贴边时：没有按钮、不能缩放、不显示正文。书签头是该便签颜色的实心头，靠屏幕内侧两角使用与便签纸面一致的小圆角；有名称时在签上横排显示一小段（认得出是哪张即可），没有名称就是纯色头。

多显示器：吸到横条当前所在那块屏的工作区左/右缘，避开任务栏 / Dock；重启恢复贴回原来那块屏（`dock.x` 认屏），屏被拔掉后夹到剩下的屏上。

多张便签贴同一侧且书签头会重叠时，后贴的那张沿边向下错开至少 40px（签高 32px + 8px 间隙）；到底部不够错就向上找空位。实在没有空位，允许轻微重叠，但后贴的那张至少露出 24px 可抓高度。

## 窗口几何

贴边窗口固定宽 96、高 32，不可缩放。休息位一半探出屏外：左缘 `workArea.x - 48`，右缘 `workArea.x + workArea.width - 48`；露出位整条贴边：左缘 `workArea.x`，右缘 `workArea.x + workArea.width - 96`。`y` 为拖入时横条上沿，再夹到工作区垂直范围内。多屏共边时隐藏半幅会漏到邻屏，退回 48 宽全露（窗口收成只有可见头那么宽，不留透明死区）。

横条与书签头都由原生拖窗整窗平移。拖动全程零写窗；吸附/钉回都在「松手 + 停稳」确认后执行——macOS 没有拖动结束事件（`moved` 是 `move` 的别名），松手由**物理按键监视器**权威判定（`CGEventSourceButtonState` 只读状态，8ms 轮询的 native helper 子进程流式上报 down/up；无需辅助功能权限；helper 崩溃/缺失时降级为「光标离开抓取点」启发式）：

1. 松手归属：物理按下时光标在窗口 ±4px 内才置位 `pressOnWindow`，物理抬起只处理置位窗——多窗并排时不会把别窗的松手当成自己的。
2. 松手后直接武装 settle watch（物理松手已是权威，跳过光标停稳检查）：每 60ms 比对 bounds，静止满 3 拍确认拖拽尾部 move 冲刷完，再收尾——横条在吸附区 → `resolveDockYForWebContents` 预算错开 y 后执行吸附滑行（见下）；书签头位置有偏 → 180ms 惰性滑回钉边。比对期间窗口被系统动过（如 macOS 拉回屏内）或用户重新按住（isDown 每拍第一查）就不动。
3. 吸附滑行只滑位置、不逐帧改尺寸：窗口全程保持横条尺寸纯平移 320ms 到「书签头角与贴边矩形精确对齐」（逐帧 resize 逼 renderer 逐帧重排 + macOS 逐帧重算阴影 = 抽动根因，不许回来），书签头 DOM 钉保留角与横条壳交叉淡变（同拍 320ms），到位后 `setDocked({kind:'dock'})` 一次性裁掉透明/空置区——裁剪区已透明，视觉零跳变。滑行期 `setHasShadow(false)`（大窗逐帧平移的阴影重算是「一格一格爬」的来源），收尾恢复。
4. 书签头水平离边达到 48px（过 8px 手抖回差带）：立即展开——`dock-applied` 带 `expandFrom`（书签头在新窗口坐标系的矩形），`setDocked({kind:'expand'})` 一帧把窗口拉满（活拖拽中多帧写窗是红线），可见运动全在 DOM：主壳同 commit 隐身（opacity 0，仍可命中拖动）+ 占位书签头钉 `expandFrom`，视口长开后 clip 钉书签头矩形、同 commit 恢复可见（首帧即书签头，不闪纸面），WAAPI 340ms 揭示到全窗；展开期关阴影 380ms。
5. 任何滑行（吸附/钉回/探头）途中被抢拖：物理 onPress 熔断（epoch 代际令牌作废旧会话全部 await 间隙），偏离滑行走廊的第一帧 move 兜底熔断；吸附滑行被熔断**不提交 dock**（commit 里的 setBounds 在活拖拽中是写窗红线），恢复义务记在 `pendingStripRestore`，拖拽结束且没停进吸附区时恢复横条几何与 DOM。
6. 几何落定后主进程发 `sticky-notes:dock-applied`（吸附带 `morphFromStrip` 目标书签头尺寸、展开带 `expandFrom`），renderer 只切 DOM 与演 DOM 动画；悬停探头纯几何，不切 DOM。

## 数据

`NoteRecord` 增加可选字段，缺省等于未贴边：

```ts
dock?: {
  side: 'left' | 'right'
  y: number   // 夹取后的书签头上沿（屏幕坐标）
  x?: number  // 静止位 x：多屏认屏证据；旧记录没有，恢复退化为 y 距离猜屏
}
```

规则：

- `bounds` 始终表示最后一次展开态的位置和尺寸。进入贴边、沿边滑动，都不改 `bounds`。
- 从贴边展开后，用展开时夹取过的矩形写回 `bounds`，并删除 `dock`。
- 进入贴边时写入 `dock`，`side` 为命中的那一侧，`y`/`x` 为当前静止位；沿边滑动时 `dock` 经 bounds 变化防抖持久化跟随当前位置。
- 读取时：`side` 不是 `'left' | 'right'`，或 `y` 不是有限数字，则整段 `dock` 丢弃，当展开打开；`x` 不是有限数字只当缺省，不拖垮整段。
- 旧便签没有该字段，无需迁移。
- 启动时若有合法 `dock`：对每块屏的工作区各算一次候选贴边矩形，中心仍落在该工作区内的才可选；有 `dock.x` 时按 |候选.x - dock.x| 认屏（同名边每屏都有一条，y 距离常打平），否则按 y 距离猜屏。算不出任何可见候选则丢掉 `dock` 按 `bounds` 展开。

## 进程边界

- 主进程扩展现有 `note-window-collapse` 控制器，增加 `docked` 态和 `setDocked` / 启动恢复入口。窗口最小尺寸在贴边时改为贴边矩形尺寸，离开贴边后恢复现有 `NOTE_MIN_WIDTH` / `NOTE_COLLAPSED_HEIGHT` 或展开最小尺寸。
- 三个态的窗口拖动都是原生 `-webkit-app-region: drag`；按钮、命名输入与命名热区保持 `no-drag`。renderer 不参与窗口移动，也没有 start/move/finish 拖动 IPC。
- 贴边恢复不能出生即贴边：出生就是小条 + 不可缩放 + 整页拖窗区的窗口在 macOS 上收不到任何 OS 鼠标事件（实测 enter/click 全丢），先按普通窗口创建、趁 show:false 改成贴边几何的窗口事件正常（与运行中新贴边的窗口同生命周期）。
- 吸附/钉回全部在主进程：拖动中的 `move` 只做判定与预览（横条用 `resolveCollapsedDockSide` 判吸附区发 `dock-preview`；书签头用 `resolveDockedEdgeOffset` 判展开），不写窗；写窗集中在松手收尾（settle watch → 吸附滑行 / 惰性钉回）与展开触发两处。物理按键监视器是独立 native helper 子进程（`native/mouse-state.c` 编译为 `bin/mouse-state-darwin-arm64`，只读 `CGEventSourceButtonState`，8ms 轮询，stdout 流式上报；父进程死亡后 helper 8ms 内自杀，`before-quit` 兜底 dispose；崩溃/退出即降级，打包经 `build.mac.extraResources` 随包分发，仅 darwin）。阈值与矩形计算放在 `shared/note-dock.ts`，主进程与测试共用。任何过渡进行中（inFlight + epoch 代际令牌）忽略冲突事件，避免重入与旧会话迟到写状态。
- 几何落定后主进程发 `sticky-notes:dock-applied`，renderer 收到只切 `dock` state 并按 payload 演 DOM 动画（吸附 `morphFromStrip` → 交叉淡变；展开 `expandFrom` → clip 揭示；裸 `{dock}` → 直接切）：贴边渲染书签头、展开渲染完整便签。悬停探头不借道 `dock-applied`，也不演壳体过渡。
- 贴边态 renderer 只渲染环+芯书签头（可选横排名称），不挂载命名组件、工具栏或正文。
- 过渡失败或 `setBounds` 失败时，控制器回滚到进入这次过渡前的状态和窗口矩形，与现有收起失败回滚一致。不得留下 96px 宽却仍挂着完整便签 DOM 的窗口。
- 不把贴边几何写进 `personalization.json`，也不改系统窗口标题规则。贴边时系统标题仍用便签名或“悬浮便签”。

## 验证

自动验证至少覆盖：

- `dock` 字段的读取归一化：缺字段、非法 `side`、非数字 `y`、非法 `x` 降级缺省、合法左右侧与 `x` 往返。
- 横条是否贴边的阈值（探出缘 8px，顶底不吸）。
- 书签头是否展开的阈值（水平离边 48px）以及未过阈值沿边滑动（x 钉边、y 夹取）。
- 悬停探头的休息/露出矩形与多屏共边 48 全露回退。
- 左贴边往右长、右贴边往左长的目标矩形，以及工作区夹取。
- 启动恢复：合法 `dock` 进贴边；多屏同名边 y 打平时按 `dock.x` 认屏；显示器丢失后夹到剩下的屏；夹不住则回退展开。
- 两张书签头重叠时的纵向错开。

## 风险

- 初版 8×56 细缝在 Mac 真机上既难抓也不像便签；中间一版 36×96 竖胶囊又被真机否掉（"应该是横的"），现为 96×32 横书签头（宽 96 伸进桌面，高 32 沿边，明显扁于竖条），有名字露出一小段。再大就会重新挡内容，不再加大。
- macOS 工作区与菜单栏、Windows 工作区与任务栏必须用 `workArea`，不能用完整 `bounds`，否则会吸到系统栏底下。
- drag 区在应用非激活时收不到 enter/leave（悬停探头曾因此整面失灵），no-drag 区 leave 也非 100% 可靠——悬停进出都不能只信事件，必须以光标真相复核，露出期要有兜底轮询。
- macOS 在 show 时会把探出屏右缘的窗口拉回屏内（4222→4174，恰好 48px），会触发一帧非拖动 move；任何「位移过阈值」的判定都要先确认是用户拖动（光标在窗内），否则启动恢复会误展开并丢 dock。
- 原生拖拽会话进行中争写 `setBounds` 两头都坏：写**被吞**一半 = 窗口在拖拽锚点与写入帧之间来回跳（抽搐），末帧被吞 = 定格半帧尺寸（184×36 变形那次）；写**中** = 窗口位置每帧被重置，「拖离 48px 展开」这类位移判定永远攒不到阈值（拖不出来）。多帧滑行同病。结论：move 流上任何逐帧写窗都不可行，滑行途中用户抢拖必须立即熔断、把几何交还拖拽。
- **bug 2（快速拖贴边抽搐/变形）已解（2026-08-21 过验收）**：根因是「磁吸不等松手」目标本身——几何改写必然落在原生拖拽会话进行中，写中被吞/写中必坏，三轮修补（snap + 校验补写、停歇钉回、release watch 光标启发式）都只是换姿势撞同一堵墙。终版改「松手才吸」：物理按键监视器（`CGEventSourceButtonState`，只读无需权限）给出权威松手信号，拖动全程零写窗，吸附/钉回全部推迟到松手 + 停稳后执行，拖动手感一次过验。教训：macOS 原生拖拽会话与 setBounds 写窗不可并发，「拖动中立即改几何」类需求只能把可见运动挪进 DOM（透明窗口）或推迟到松手。
- **动画手感三条实测真相（2026-08-21）**：①frameless + transparent 在 Mac 默认有阴影，逐帧 setBounds = WindowServer 逐帧重算阴影——小窗（96×32 peek）无感、大窗（横条）肉眼可辨「一格一格爬」，动画期 `setHasShadow(false)` 是廉价特效药；②大透明窗一帧 setBounds 拉满的首帧要分配 backing store + 重算阴影，clip/遮罩必须在这帧之前就位（同 commit 隐身 + 占位书签头），否则用户先看到一闪纸面再开始动画——「掉帧」常发生在动画开始之前；③clip-path（含 round）在 Chromium 常走主线程 paint，大窗每帧重绘超预算就丢帧，拉长时长（260→340ms）稀释每帧位移比换属性更安全——整壳 transform 会打废 `-webkit-app-region`（活拖拽红线），不能用。
- **「刚吸附落位马上拖不出来」（2026-08-21 修）**：吸附落位后 ~280ms morph 切 DOM，Chromium 对光标下的新书签头元素补发 mouseenter → 触发悬停探头复核；旧护栏只看 move 流/settle watch，不看物理按键——按下书签头、move 还没流第一帧的空档里探头滑行起跑 = 多帧写窗撞原生拖拽会话。修法：探头复核加 `isDown` 物理护栏，按住时记 pending、拖拽收尾用光标真相补复核。
- 贴边是第三态，收起动画的回归（基础态禁止 `height` 过渡、展开尺寸不得被 40px / 32px 写进 `bounds`）继续有效。
