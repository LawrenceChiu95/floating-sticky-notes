# 收起横条贴边吸附

## 背景

现有收起把便签变成仍留在桌面上的 40px 标题横条。横条置顶、可拖、可命名，但大部分时间挡在桌面或窗口上；截网页或应用窗口时也容易拍进去。

用户日常只在做完一件事时才需要把待办拖出来打勾，其余时间希望它像安全管家加速球一样吸在屏幕侧面，只露一条边。

本设计处理 [Issue #24](https://github.com/LawrenceChiu95/floating-sticky-notes/issues/24)。

## 目标

- 已收起的横条可以吸到当前屏幕左或右工作区边缘，收成一枚可拖的彩色书签头。
- 从书签头拖过阈值松手后，在松手位置丝滑长成上次展开的宽高，便于直接打勾。
- 贴边状态写入 `notes.json`，重启后仍是书签头；只收成横条、未贴边的便签重启后仍展开。
- 贴边后截某个窗口或页面时，不再拍到 40px 横条。
- 贴边与现有收起共用同一套窗口编排，不引入第二套 `setBounds` 动画。

## 非目标

- 不从展开态直接贴边，也不提供贴边回到横条的专用动作。
- 不吸顶边或底边。
- 不把横条收起状态写入 `notes.json`。
- 不调用 `setContentProtection` 或任何“从截图/录屏中排除窗口”的 API。
- 不做悬停探出、全局快捷键呼出、点击书签头展开。
- 不改变安装身份、`userData` 路径、开机启动或更新流程。
- 第一版不为多张贴边便签做智能分组；只在即将重叠时沿边错开，保证都能抓住。

## 已选方案

在现有收起控制器上增加第三态，窗口状态为：

`expanded` → `collapsed`（40px 横条）→ `docked`（左/右 96×32 横书签头）

贴边复用收起的编排：renderer 负责过渡视觉，主进程只在过渡两端各做一次非动画 `setBounds`。不使用 Electron `setBounds(..., true)`，也不在拖动过程中逐帧改窗口形态。

## 人怎么用

| 状态 | 外观 | 是否持久化 |
| --- | --- | --- |
| 展开 | 现有完整便签 | `bounds` 记展开位置和尺寸 |
| 横条 | 现有 40px 标题横条 | 不记；重启当展开 |
| 贴边 | 工作区左或右缘一枚 96×32 彩色书签头，颜色跟随该便签 | 记 `dock.side` 与 `dock.y` |

进出：

- 展开 ↔ 横条：现有收起按钮，行为不变。
- 横条 → 贴边：拖横条，使其左缘进入当前屏工作区左缘 24px 内，或右缘进入右缘 24px 内，松手后吸住并收成书签头。未到阈值则保持横条。
- 贴边 → 展开：拖书签头。沿水平方向进入工作区不足 48px 就松手，弹回贴边；达到或超过 48px 则在松手位置用上次展开宽高长开。
- 左边贴边往右长，右边贴边往左长，长开后再夹进工作区，避免先冲出屏幕再回弹。
- 不允许展开 → 贴边，也不提供贴边 → 横条。

贴边时：没有按钮、不能缩放、不显示正文。书签头是该便签颜色的实心头，靠屏幕内侧两角使用与便签纸面一致的小圆角；有名称时在签上横排显示一小段（认得出是哪张即可），没有名称就是纯色头。

多显示器：吸到横条当前所在那块屏的工作区左/右缘，避开任务栏 / Dock。

多张便签贴同一侧且书签头会重叠时，后贴的那张沿边向下错开至少 40px（签高 32px + 8px 间隙）；到底部不够错就向上找空位。实在没有空位，允许轻微重叠，但后贴的那张至少露出 24px 可抓高度。

## 窗口几何

贴边窗口固定为 `96×32`，不可缩放。`x` 贴齐工作区左缘或 `workArea.x + workArea.width - 96`；`y` 为拖入时横条上沿，再夹到工作区垂直范围内。

横条拖动本身保持整窗平移，形态不变。是否贴边只在松手时判定，避免拖动中途把 280×40 的横条收成书签头、跟手打架。

从贴边拖出时，书签头先跟着指针平移（仍是 96×32）。松手后：

1. 未过 48px 水平位移：书签头动画回到原贴边位置，窗口矩形不变。
2. 已过阈值：先算出目标展开矩形并夹进工作区；夹不住则保持贴边，不进入半展开。夹住后主进程先一次 `setBounds` 到该矩形（透明窗外的多余区域不可见），renderer 再把壳体从书签头的视觉尺寸用约 240ms 长到满窗。必须先放大窗口再演视觉，否则 96×32 的窗口会裁掉展开动画。
3. 左边贴边锚左上往右长，右边贴边锚右上往左长。

横条 → 贴边方向相反：renderer 先把横条视觉收到 96×32，主进程再在过渡结束时一次 `setBounds` 成贴边矩形。若先缩窗口，280px 横条会被立刻裁掉。

## 数据

`NoteRecord` 增加可选字段，缺省等于未贴边：

```ts
dock?: {
  side: 'left' | 'right'
  y: number
}
```

规则：

- `bounds` 始终表示最后一次展开态的位置和尺寸。进入贴边、在贴边中拖动、弹回贴边，都不改 `bounds`。
- 从贴边成功展开后，用松手后夹取过的展开矩形写回 `bounds`，并删除 `dock`。
- 进入贴边时写入 `dock`，`side` 为松手时命中的那一侧，`y` 为夹取后的书签头上沿（屏幕坐标）。
- 读取时：`side` 不是 `'left' | 'right'`，或 `y` 不是有限数字，则整段 `dock` 丢弃，当展开打开。
- 旧便签没有该字段，无需迁移。
- 启动时若有合法 `dock`：先按所在屏夹取 `y` 与侧边；夹取后书签头仍完全落在某块可见工作区内则直接以贴边态创建窗口，否则丢掉 `dock` 按 `bounds` 展开。

## 进程边界

- 主进程扩展现有 `note-window-collapse` 控制器，增加 `docked` 态和 `setDocked` / 启动恢复入口。窗口最小尺寸在贴边时改为 `96×32`，离开贴边后恢复现有 `NOTE_MIN_WIDTH` / `NOTE_COLLAPSED_HEIGHT` 或展开最小尺寸。
- renderer 只在横条态松手时请求“若已到边缘则贴边”，只在贴边态松手时请求“若已过阈值则展开，否则弹回”。判定阈值的几何计算放在 `shared/`，主进程与测试共用，renderer 不各自发明一套。
- 收起横条与贴边书签头的窗口拖动不走 `-webkit-app-region`：renderer 只报告手势开始（带抓取偏移）与松手，拖动期间主进程自己跟着光标移动窗口，避免逐帧 IPC 移窗的卡顿；贴边/展开/弹回判定仍只发生在松手那一次。展开态横条继续用原生 `-webkit-app-region: drag`。
- 贴边态 renderer 只渲染一枚着色书签头（可选竖排名称）和拖动手势，不挂载命名组件、工具栏或正文。
- 过渡失败、`setBounds` 失败或 IPC 未确认成功时，控制器回滚到进入这次过渡前的状态和窗口矩形，与现有收起失败回滚一致。不得留下 36px 宽却仍挂着完整便签 DOM 的窗口。
- 不把贴边几何写进 `personalization.json`，也不改系统窗口标题规则。贴边时系统标题仍用便签名或“悬浮便签”。

## 验证

自动验证至少覆盖：

- `dock` 字段的读取归一化：缺字段、非法 `side`、非数字 `y`、合法左右侧。
- 横条松手是否贴边的阈值（左右缘 24px，顶底不吸）。
- 书签头拖出是否展开的阈值（水平 48px）以及未过阈值弹回。
- 左贴边往右长、右贴边往左长的目标矩形，以及工作区夹取。
- 启动恢复：合法 `dock` 进贴边；显示器丢失后夹不住则回退展开。
- 两张书签头重叠时的纵向错开。

自动验证通过不等于 Windows / macOS 真机手感通过。贴边吸附、拖出长开、多显示器边缘和截窗口时是否还拍到横条，必须在目标环境分开记录。

## 风险

- 初版 8×56 细缝在 Mac 真机上既难抓也不像便签；中间一版 36×96 竖胶囊又被真机否掉（"应该是横的"），现为 96×32 横书签头（宽 96 伸进桌面，高 32 沿边，明显扁于竖条），有名字露出一小段。再大就会重新挡内容，不再加大。
- macOS 工作区与菜单栏、Windows 工作区与任务栏必须用 `workArea`，不能用完整 `bounds`，否则会吸到系统栏底下。
- 贴边是第三态，收起动画的回归（基础态禁止 `height` 过渡、展开尺寸不得被 40px / 36px 写进 `bounds`）继续有效。
